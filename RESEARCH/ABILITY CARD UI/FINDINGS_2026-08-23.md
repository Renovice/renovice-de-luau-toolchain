## Decompiler boundary for UI rows

The 2026-08-24 controlled hot test changed the already-loaded Mallet module
from `Overguard Damage Gain = 10%` to `Damage To Overguard = 1%`. The live card
retained the old row after F9. This does **not** identify a decompiler defect:

- `BardMusic_mallet_addon_dispatch.luau` recompiles to 33,771 bytes and 24
  prototypes and reparses successfully;
- focused Warframe API checking reports `violations=0`;
- `plan-verify` reports `status=MANIFEST_OK` and `failures=0` on prototypes
  0 through 23;
- `de-roundtrip` reports `consts re-encode exact: 24/24` and
  `FULL BODY identical: True`; and
- an earlier full restart rendered added native rows correctly, proving that
  `GetAbilityUpgradeLevelInfo` row generation is understood by the current
  compiler and accepted by the client.

Therefore UI rows do not need a separate opcode, renderer, AST node, or
decompiler pass. The unresolved problem is runtime ownership: F9 must make the
client's native loader refresh the already-existing UI/script objects associated
with the original resource descriptor. The source bootstrapper investigation
and loader disassembly live under
`Boostrapper Source Edited/RENOVICE_MIGRATION`, not in this decompiler.

## Direct native-row F9 result

The first live F9-only check still showed no added native rows. This does not
match a missing-build hypothesis:

- the live replacement hash is exactly
  `5017FAC35065AB022B9B7776078220D6DD75A8841CE90CFA3490365DE1C7B219`;
- the live bytes contain both
  `/Renovice/AbilityStats/OverguardCap` and
  `/Renovice/AbilityStats/DamageToOverguard`;
- the live bytes do not contain `RENOVICE_AUGMENT_ABILITY_CARD`;
- F9 committed generations 70, 71, and 77–80 with `addons=0` and
  `module_refresh=PASS`;
- the screenshot still showed only the four stock rows.

Bootstrapper source resolves the discrepancy. `LoadedContext` stores both an
environment and `state->global_state`. `reexecute_changed_loaded` calls
`compatible_hot_reload_vm`, which requires pointer equality between the F9
drain's global state and the captured context. Nonmatching contexts increment
`deferred`. The older function returns the execution `pass` flag without
making deferred contexts fail the generic PASS result.

**Conclusion:** the Arsenal/UI module instance was not refreshed by this F9
drain. The next test is a full client restart with no byte changes. Startup
loading will distinguish the VM-refresh limitation from a genuine native-row
format problem.

A full client restart rendered both additional native rows, proving the row
architecture live. The displayed values were correct (`15.000` under the
client locale and `10%`), but the new localization paths were printed as raw,
normalized paths. This separates two hypotheses:

- native-row insertion is **TRUE live**;
- CAT replacement data can register brand-new localization keys is **FALSE

## Native-descriptor F9 and final label result

After correcting the bootstrapper to reuse the original native module
descriptor, the same running client successfully refreshed Mallet's native row
from `Overguard Damage Gain = 10%` to `Damage To Overguard = 1%`, then to the
final shorter label `Overguard From Damage`. No process restart was used.

The final label build is 33,773 bytes with SHA-256
`4ABD68124FBB350D03ED4E3F57BF6431FF9B96F804C9DC57918183A8C1BB6016`.
It reparses, passes all 24 semantic plans with zero failures, has zero focused
API violations, re-encodes all 24 constant sets exactly, and reports a fully
identical DE body. The persistent runtime log records native module refresh
PASS, one VM-local execution, zero failures, zero pending work, and committed
module-refresh PASS.

The row's normalization/scaling contract is documented in
`Boostrapper Source Edited/RENOVICE_SCRIPTING/CARD_UI/NATIVE_ABILITY_CARD_ROWS.md`.
The implementation uses `0.01` as the canonical gameplay fraction, converts to
percent only at the UI row, applies the evidence-backed Mallet
`ModifyValue(..., 10, suit:GetType(), suit)` Strength path in both gameplay and
modded card queries, and clamps the result to `0.05`. The label and F9 path are
live-proven; explicit base-versus-modded value progression remains a separate
live acceptance check.
